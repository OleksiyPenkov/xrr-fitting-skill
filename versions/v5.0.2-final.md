# XRR fitting procedure of this laboratory

This is the laboratory's procedure for fitting a measured X-ray reflectivity curve with the `xrc` tools. Follow the sections in order. Each step names the tool parameter that carries it and the reason in one clause. Where the procedure and a tool's own description disagree, the procedure wins. Every laboratory, instrument, substrate and material constant comes from a preset file, which must validate against `preset.schema.json`, and from the substrate library the preset names in `substrate.library`, which must validate against `substrates.schema.json`; the rules in this text are general and carry no constant of their own. Load and validate the preset before section 1, and record its `preset_id`, the SHA-256 of the preset file's raw bytes and the id of the substrate used in report slot 1 (section 13).

## 1. Read the curve

1. Call `list_measurements`, then `get_measurement` for the curve with `max_points` 2000. Every later step reads from this curve.
2. In the critical-angle range (θ below `instrument.auto_theta_max_deg`) find the angle of the measured maximum; call it θ_max and record the intensity there as I_max (counts). This point anchors the normalization (section 4) and the low-angle limit of the fitting range (section 6).
3. Record the background level: the median of the intensities above the last visible order, in counts, floored at one count, because a background read as zero makes the visibility test of section 6 meaningless. It sets the floor `r_min` in section 6. **On an `.xrdml` import this median is not a measurement.** The server floors every non-positive point to the smallest positive intensity seen before it, so a tail whose true content is zero counts comes back as the last positive value repeated; the header says how many points were floored. Read the count unit from the header instead (rule 5) and take the background as one count, which is what the tail actually contains. A curve with more floored points than visible orders carries no background information at all, and section 6's `r_min` is then a floor you have chosen rather than one you have measured — say so in report slot 2.
4. **A curve imported from an `.xrdml` brings its own wavelength, and it wins.** The server reads the optic
   and the emission lines out of the file: with `usedWavelength@intended` "K-Alpha", `ratioKAlpha2KAlpha1`
   present and no monochromator or `hybrid="true"` mirror in the incident path, it uses
   (kAlpha1 + r*kAlpha2)/(1+r), otherwise kAlpha1, and reports which rule fired in `lambda_source`. On this
   laboratory's Empyrean that gives 1.541874, which is `instrument.lambda_A` to five decimals — so the
   preset's wavelength is not a lab convention, it is derivable from any measurement file. **A `lambda` in
   `meta.json` no longer overrides an `.xrdml`**; the server reports the differing value as not used. To fit
   at a wavelength of your own choosing, pass it as `fit_xrr`'s `lambda`, and say in report slot 1 why.
5. **A curve imported from an `.xrdml` does not arrive in counts.** The server divides by the counting time and normalizes the curve to 1 at its global maximum, which is a presentation scale for the graph and is never a measurement anchor: the fit re-anchors at a named angle through `scale: "auto"` and `auto_theta_max` (section 4). Two consequences for this section. First, do not read the normalization as a plateau: the global maximum is the plateau on a well-aligned specimen and the **first Bragg order** on a specimen whose plateau is depressed by alignment, and nothing in the curve says which. Second, the count unit has to come from the header, which carries the peak count rate and the counting time: **one count = 1 / (peak count rate x counting time)** on the normalized scale. Read I_max, the background and the one-count floor of rule 3 in those units, and report the peak count rate and the counting time in report slot 2 beside them. A curve read from a text file is already in counts and needs none of this.
6. **The plateau is not guaranteed to be there, and is not guaranteed to be right.** If the highest visible Bragg order stands above the maximum below `auto_theta_max_deg`, the plateau is depressed — true reflectivity cannot exceed its total-reflection value — and `I_max` is not a safe scale anchor. Report the ratio. It costs nothing: both numbers are already read here. The depression follows specimen alignment, so it is a property of the measurement and not of the sample, and it cannot be recovered from the file (v5 4.3).
4. The curve file is in 2θ and the server converts it to θ. Every angle you pass to `fit_xrr` or `calc_reflectivity`, including θ_max and `theta_range`, is θ, never 2θ.
5. Identify the Bragg orders by predicting each order's angle with refraction, from sin²θ_m = (mλ/2d)² + 2δ with λ from `instrument.lambda_A`: assign the measured maxima to the predicted angles, refine d and δ by least squares over the orders found, and iterate until the assignment stops changing. Spacing the orders linearly as m·θ_1 misassigns the high orders, because refraction shifts them, and a misassigned order corrupts both the period and the fitting range (section 6).

## 2. Starting model

1. Substrate: the entry of the substrate library `substrate.library` named by the job, or the one named by `substrate.default` when the job names none; its `material`, `density` and `sigma_A` are read from there and held fixed. `fit_xrr` cannot free the substrate; the library's `sigma_A` is a starting value for this laboratory's stock, not a property of the material, so you do not vary it.
2. Layers: from the nominal design, thickness, order and period count as deposited. These are the start values of every free parameter in section 7. Give each layer a density near the bulk value of its material.
3. On top of the stack, a light surface layer taken from `surface.contamination_layer`: its `material`, `thickness_A`, `sigma_A` and `density`, as its own stack with N 1 listed after the periodic stack. Include it according to `surface.contamination_layer.include`: always, never, or only when the critical edge or the fringe field between the orders is not reproduced without it. It stands for the hydrocarbon contamination every surface carries in air; without it the fringe fields between the orders do not fit. Its thickness, sigma and density are free, with the bounds of `surface.contamination_layer.bounds`, which are its own and not the material bounds of `materials`: a hydrocarbon overlayer is lighter than the sputtered form of the same element.
4. A cap that belongs to the design is taken from the design and is not this contamination layer.
5. `polarization` "s": at grazing incidence s and p give the same reflectivity, and the s-only calculation runs twice as fast.
6. `lambda` from `instrument.lambda_A`.

## 3. Before the first fit of a new structure type: sensitivity check

1. Before your first fit of a structure type, compute variants of the starting model with `calc_reflectivity`, one change per variant: period +2 % and −2 %; the layer ratio both ways at the same period; each layer's sigma at the two ends of `materials.sigma_A.bounds`; each layer's density +15 % and −15 %; a surface layer at the `thickness_A` and `density` of `surface.contamination_layer.sensitivity_variant`, which differs from the starting layer so that the variant probes something; N halved and doubled. Use the same `lambda`, polarization and resolution as the fit.
2. For each variant write down which feature of the curve moved: the Bragg peak positions, the relative heights of the orders, the heights of the highest orders, the level between the peaks, or the shape of the critical edge. Only the feature, not the numbers.
3. Two rules for reading this map and, later, a fit:
   - Peaks have priority. The level between the peaks is set by the ends of the stack, the top layer and the substrate side, not by the period structure. A mismatch between the peaks is corrected at the top layer or the substrate side, not by moving the period structure.
   - Larger diffraction orders carry the smaller details. The first order fixes little beyond the period; the higher orders carry the layer ratio, the interface widths and any drift through the stack.
4. Keep the map: it tells you which parameter to move when a fit disagrees with the data (section 10). Report it (section 13, slot 3).

## 4. Normalize (scale)

1. `scale: "auto"` in every `fit_xrr` call, with `auto_theta_max` from `instrument.auto_theta_max_deg`. The server finds the measured maximum below that angle, computes the starting model at that angle and sets scale = R_calc(θ_max) / I_max: the measured maximum on the plateau is set equal to the model at the same angle. The result echoes `scale`, `scale_theta` and `scale_counts`; report all three, and check that `scale_theta` equals the θ_max of section 1 and `scale_counts` equals I_max. The value must be sent as the JSON string `"auto"` (quoted) and `auto_theta_max` as a number (unquoted); every numeric argument of every tool is sent unquoted, a quoted number is refused. Where the server offers the boolean `scale_auto`, send `scale_auto: true` instead of the string; it does the same and reports the same three values. If the call is refused as invalid JSON, send instead the number R_calc(θ_max) / I_max computed in section 6, which is the same division the server makes; then `scale_theta` and `scale_counts` are yours to report from section 1.
2. The scale is computed from the starting model, so it belongs to that model. Renormalize when, after a fit, the edge check of section 10 shows the fitted model's plateau and edge region no longer overlapping the measured curve: run the fit again with the fitted structure as the starting model and `scale: "auto"`, which recomputes the scale against it. This is a judgment made after each fit, not a fixed count.
3. **The scale is solved inside the objective, within a window around the anchor.** Send `scale_solve` from `scale.solve` and `scale_solve_window` from `scale.solve_window` in every `fit_xrr` call, never relying on the engine's default for either. With the solve on, the engine scores every candidate structure at the multiplier of the anchored scale that minimises its chi-squared, found in closed form and held within a factor of (1 + window) of the anchor either way, so the anchor of rule 1 is where the search starts and not what it returns. Reason (`scale.reason`): the plateau maximum is not a measurement of the scale. A plateau depressed by alignment (section 1, rule 6) goes straight into every fitted density when the scale is held at it, and against a wrong anchor the solve caps the damage at its own bias; the grounds are in the preset. Report `chi2_scale`, `scale_ratio`, `scale_clamped` and `scale_solve_window` with every fit (section 13, slot 5). A fit whose scale ends on the window's bound (`scale_clamped` true) has not solved its scale: report it as clamped and look first at the range end of section 6, because a tail that sits on the count floor drags the solve, and only then at the model.
4. **A chi-squared threshold fixed with the scale anchored does not carry to a solved scale.** For the same structure the solved chi-squared is never higher than the anchored one. `acceptance.calibrated_under.scale_solve` records which of the two `chi2_max` was fixed under; when it differs from `scale.solve`, the verdict of section 10 states that the threshold is applied outside its calibration (section 10, rule 5).

## 5. Smooth

1. `smooth {"passes": smoothing.passes}` in every `fit_xrr` call. The preset sets it to **0: smoothing is off**, and the preset carries the measurement it is off on. Send the key explicitly rather than relying on a server default, and report the value with the fit (section 13, slot 6).
2. There is **no condition under which to switch it on**, and the preset offers no threshold key. A pass was expected to pay on a dim curve and does not: measured across four brightness levels with the fitting range held so that only the counting noise varies, one pass is the better of the pair in fewer than half the paired comparisons at every level, and the dimmest curve is among the worst. The grounds are in `smoothing.reason`.
3. What a pass costs, if one is run anyway: the period is what it damages most, and a heavy layer's density is pushed up because smoothing raises a convex curve's minima and the fit compensates (section 7.6 reads a density at its ceiling partly this way). Report that a pass was run, and treat any density near its bound as conditioning rather than structure.
4. Only the engine's default window was tested. "Off" is measured against one default pass, not against a narrower window, so a narrower window is an open question and not a settled alternative.
5. The tool applies scale, then smooth, then the trim, which gives the same curve as smoothing first. With `passes` 0 the order is immaterial.

## 6. Low limit and fitting range

1. `r_min` = one count × scale, i.e. at or just below the measured background after normalization. For the first fit compute the scale for this purpose as R_calc(θ_max) / I_max from one `calc_reflectivity` of the starting model over the critical-edge region (at least 400 points, the resolution of section 8), the same division the server makes; for later fits use the echoed `scale`. Never carry an `r_min` over from another curve or another scale.
2. Reason: a floor above the measured background clips the calculated curve where the data fall lower, and a floor below the background makes the residual in the tail one-sided. Both show in the residual by band of section 10.
3. `theta_range.min` = θ_max, so the fitting range includes the critical edge. Exception, a single film of the light material only: `theta_range.min` = `single_film.theta_min_deg`, because the simulated edge of such a film shows a shoulder the measured curve does not have.
4. `theta_range.max` covers at least the first `fitting_range.min_predicted_orders` Bragg orders **predicted** by section 1's refined period and 2δ, whether or not the curve shows them, and never runs past the measured end. When at least that many orders stand `acceptance.thresholds.order_visible_factor` times above the background level of section 1, the range ends a quarter of the spacing between orders past the last visible one — the end every fit of the recovery benchmark was run with (earlier revisions of this rule said "half"; the implementation was always a quarter, and it is the measured quantity that is stated here). When fewer are visible, it runs on to half a spacing past the last of the required predicted orders, where the missing ones would be. Reason: an order the model predicts and the data do not show is evidence about the layer ratio and the interfaces, and the residual can only use it if the range reaches the angle where the model promises a peak. Measured (benchmark stages H2–H4, `fitting_range.reason`): a curve with seven visible orders loses from any extension, so the range is not simply "longer"; a curve with three to six gains up to the seventh predicted order and loses again past it. The rule holds for the preset's weighting as shipped (`chi2.multilayer.point_weight` on) and not with it off. For a film the range ends past the last fringe that stands `order_visible_factor` above the background, unchanged.
5. Trim after normalizing and smoothing: θ_max and the smoothing pass are read from the untrimmed curve.
6. Before the first fit, seed the period from the curve, not from the design. Take the orders whose index is unambiguous, the strong low orders; fit sin²(θ_m) against m² by least squares; read the period from the slope and 2δ from the intercept. Check the critical angle implied by 2δ against the measured edge of section 1 and, if they disagree, drop the highest orders and repeat. The result is the start value of the period in the starting model (section 2) and the centre of the period bound of section 7, because the period is the parameter the Bragg peak positions fix most tightly and a period seeded from the design rather than from the curve can leave every calculated peak displaced.

## 7. Free parameters and bounds

1. Free the thickness, sigma and density of every layer, the surface layer included. In periodic mode also free the period of the repeating stack (`"target": "period"` in `free`, bounds in Å).
2. Bounds are generous: thickness ± one third of the expected value; sigma `materials.sigma_A.bounds` (`single_film.sigma_bounds_A` for a single film); period ± 10 % of the expected value. Every start value lies inside its bounds; start sigma within `materials.sigma_A.start`.
3. Density bounds and start value carry no material name in this text. For a material listed in `materials.named`, take `density_min`, `density_max` and `density_start` from its entry. For any material not listed there, take `materials.default_rule.min_fraction_of_bulk`, `.max_fraction_of_bulk` and `.start_fraction_of_bulk` as fractions of that material's Henke bulk density, so a new material system needs no new text. The surface layer is the one exception: its bounds are `surface.contamination_layer.bounds` (section 2).
4. Reason: the optimizer misbehaves near a bound, so bounds are not prior knowledge encoded tightly; they keep the swarm away from the edges. The one physically meaningful bound is the density ceiling at the bulk value.
5. After every fit read `report.near_bounds` in the result. **A bound a fitted value ends on is extended in that direction, and the fit is run again.** The rule holds for every free parameter, and for a value that ends within `acceptance.thresholds.near_bound_fraction` of its range from the bound as well as exactly on it: such a value was decided by the bound and not by the data. It is enough that one seed of the set reaches a bound, because the bound has then shaped the search. Repeat until no free parameter of any seed ends on or near a bound, and report every extension made (section 13, slots 13 and 17).
6. The density ceiling at the bulk value is the exception, because it is the one bound that states a physical fact rather than a search range. Raise it only with a stated reason that says why this material, as this laboratory deposits it, is denser than the table's bulk value; the preset carries such a reason where one exists (`materials.named`, as for sputtered carbon). Without a reason the fit is reported at the ceiling, and a fitted density sitting there is read as a sign that the conditioning, not the structure, is pushing it up: check the scale (section 4) and the smoothing (section 5) before the model. A density at its lower bound is extended like any other parameter, and is read with section 11, step 2.

## 8. Settings

1. `resolution` (Δθ): the instrument's beam divergence, applied as a Gaussian of that FWHM to the calculated curve. It is a tuning parameter of the instrument, not a constant: it varies between diffractometers and, on one diffractometer, between measurements. It is not a fittable parameter — the engine refuses it — and it is never inherited from another operator's project file, because such a value stands for that operator's instrument and measurement. Start at `instrument.resolution_deg.start`.
2. Choose it by scan. When the fit has converged, re-fit at each value from `instrument.resolution_deg.min` to `instrument.resolution_deg.max` in steps of `instrument.resolution_deg.scan_step` and keep the value with the lowest chi2, because the fringe contrast is one feature of the curve while the chi2 is over the whole fitting range. Every point of the scan is a re-fit and never a re-scoring of the converged structure: re-scoring hands the engine a profile fit's flattened mean structure, which discards the depth drift and gives a meaningless chi2. Run the scan from the first seed of the set only, and the full seed set once at the chosen resolution, because the scan compares resolutions and the seed set measures what one resolution leaves undetermined. Report the chi2 against resolution (section 13, slot 9). The chosen value is the one that best conditions the calculated curve to this measurement — it also absorbs the smoothing pass of section 5 — not a measurement of the beam divergence, so it is reported as a setting of this fit and not carried to another curve.
3. The fringe-contrast comparison is still computed and reported, as a check and no longer as the choice: `report.fringes` gives, for the secondary (Kiessig) fringes between the first and second Bragg orders, each fringe maximum over its neighbouring minimum and the mean contrast, measured and calculated. A calculated mean contrast larger than the measured one (deeper fringes) indicates too small a Δθ; report the comparison beside the scan and let the scan decide.
4. `seed`: run every fit from `optimizer.seeds.count` seeds, taken from `optimizer.seeds.list` when that list is given, so the run is reproducible to the last digit. The spread of each fitted parameter across the seeds, taken as the sample standard deviation over the seeds, is what the curve leaves undetermined, not an error bar of the instrument. The standard deviation and not the range, because the range grows with the number of seeds while the standard deviation does not; report it (section 13, slots 11 and 16). The reported structure is the seed with the lowest chi2, and the spread is reported beside it, because a mean over seeds is a structure no seed found.
5. `chi2`: `theta_weight` and `point_weight` from `chi2.multilayer` for a multilayer and from `chi2.single_film` for a single film; the moving-average window from `chi2.movavg_window`. Changing any of them changes what a chi2 threshold means.
6. `optimizer`: `iterations` from `optimizer.iterations`; `population` from `optimizer.population.multilayer` for a multilayer and `optimizer.population.single_film` for a single film; `range_seed` from `optimizer.range_seed`. Population before iterations: a larger population is what finds the right minimum, more iterations of a small one does not.
7. `points_inline_max` 0: the result carries no curves; the judgment of section 10 reads the result's `report`.
8. `fit_xrr` returns a job id at once. Call `job_wait` with that id and `wait_s` 300; it returns when the job has finished, or after 300 s with the job still running, in which case call it again. When the state is finished, call `job_result`. Do not poll `job_status` in a loop.

## 9. Periodic or profile mode

1. Fit every new multilayer curve in periodic mode first, with the period free.
2. Then fit the same curve in profile mode as well, always, whatever the periodic fit scored, except where this procedure states the opposite (a single film, section 12; a stack of one period). A fit costs seconds on a GPU, so nothing is saved by not running it, and the chi2 test of step 7 cannot see a drift whose layer drifts cancel: when every deposition rate drifts, the layer drifts oppose one another and the chi2 difference between the two models falls inside the seed scatter, while the period drift itself is still recovered.
3. Expect the profile fit to be the one reported when the order table (`report.orders`) of the periodic fit shows it reproducing the low orders but over-predicting the high ones: the calculated Bragg maxima standing clearly above the measured ones, and further above them the higher the order. That pattern means the layer thicknesses vary with depth, which one period cannot carry. The trigger is the shape of the discrepancy across the orders, not a ratio: no threshold is set on it.
4. A periodic fit that fails a criterion of section 10 (an order outside `acceptance.thresholds.order_band_fraction`, the edge, or chi2) may be failing because the period drifts through the stack; the profile fit of step 2 is already there to answer it.
5. The profile fit: `profile` true, `poly_order` from `optimizer.poly_order_first` and raised only when the residual demands it, `paired` from `optimizer.paired`, and, when `optimizer.lock_interlayer_thickness` is true, the thickness of every layer the design marks as an interlayer added to `paired` for that layer. Every main layer's thickness then carries a profile through the stack while sigma, density and the interlayer thicknesses keep one value per layer: a drift through the stack is a drift of the deposition rates, which changes every main layer, while the intermixing that sets the roughness and the interlayers does not drift when the growth temperature is held constant (a water-cooled substrate holder), without the period in `free` and without a period bound, same seeds and settings otherwise.
6. A profile fit does not hold the period — the profile engine lets it float — so the period is bounded through the layer thickness bounds of section 7 instead.
7. The profile fit is reported as the drifting stack when its period drift — the change of the period from the substrate end to the surface end — exceeds `reporting.model_selection.margin_in_seed_spreads` times the spread of that same drift across its seeds (section 8, step 4); otherwise the stack is reported as uniform and the periodic fit stands. The test is on the drift and not on chi2, because a drift of every deposition rate leaves the two chi2 values within the seed scatter while the period drift is still recovered, and because chi2 measures the fit to this curve rather than the quantity being claimed. The split of a period drift between the individual layers is not a reported quantity: the curve fixes the drift of the period, and which magnetron's rate drifted is settled by the deposition record.
8. A raised `poly_order` over `optimizer.poly_order_first` is kept only if it passes every criterion of section 10 and its chi2 is lower than the first-order fit's by more than `reporting.model_selection.margin_in_seed_spreads` times that fit's own chi2 spread across its seeds, because a smaller difference is not distinguishable from the optimizer's own scatter. Report both fits, both chi2 spreads, and the reason for the choice.

## 10. Judge the fit

1. Chi2 alone is not the judgment. It is one check among the following.
2. The fit result carries a `report` object (also `report.json` in the job folder), computed by the server on the fitted curve and, under `start`, on the starting model. Read it; do not recompute the curves.
3. From `report` take:
   - the order table (`orders`): for every visible Bragg order (`visible` = measured maximum at least `acceptance.thresholds.order_visible_factor` times above the background) the measured and calculated angle of the maximum, the measured × scale and calculated intensity, and the ratio calculated / measured;
   - the edge check (`edge`): measured × scale against calculated at three angles between θ_max and the first fringe minimum;
   - the fringe check (`fringes`): the contrast of each secondary fringe between orders 1 and 2 and the mean contrast, measured and calculated;
   - the residual by band (`bands`): eight equal bands of the fitting range, mean and rms of log10(calculated / measured × scale) in each;
   - `near_bounds` (section 7).
4. The pass criteria are not written here; their thresholds come from `acceptance.thresholds`. Chi2 below `acceptance.thresholds.chi2_max` for a multilayer; every visible order's ratio calculated / measured within `acceptance.thresholds.order_band_fraction` of 1; the edge within a factor of `acceptance.thresholds.edge_factor` at the three angles. A fitted density is not judged (`acceptance.thresholds.density`). Chi2 above `acceptance.thresholds.chi2_conditioning_alarm` means the conditioning is wrong: check `theta_range.min` (section 6) and the scale (section 4) first, before anything in the model. A band whose mean residual exceeds `acceptance.thresholds.band_residual_warn` in magnitude is a warning: look at the ends of the stack (section 3, rule 1).
5. Report every threshold together with the conditioning it was calibrated under, which the preset records in `acceptance.calibrated_under`: the curves, the angular range, the chi-squared weighting, the resolution and the number of orders present. A threshold carries no further than that conditioning. When the fit being judged falls outside it — a different material system, a curve carrying a different number of orders, a different weighting — the verdict states that the threshold is being applied outside its calibration.
6. Take the spread of each free parameter across the seeds of section 8, step 4. The spread measures what the curve does not fix, rather than leaving it assumed.
7. A parameter whose spread across the seeds exceeds its entry in `reporting.undetermined_precision` is reported as undetermined, not as a number, because the seeds disagree by more than the number would claim. For a profile fit the test is applied to the per-period values, not to the polynomial coefficients, which are not quantities the specimen has.
8. When `reporting.sum_not_split` is true, two adjacent layers are reported as their sum, with the split declared undetermined, whenever the spread of the sum across the seeds is smaller than the spread of either layer on its own: the seeds have then fixed the total and not the division. Two independent fits of one curve agreed on the total metal in a period to within a few tenths of an angstrom while placing the thick interlayer on opposite sides of the metal layer.
9. The curve not fixing the division does not make the two interfaces of a period equivalent. Growth is often asymmetric: a heavy material deposited onto a light amorphous underlayer and a light material deposited onto a dense or crystalline heavy one are different processes and give interlayers of different width. It is not asymmetric always: where the heavy layer is thin enough to stay amorphous rather than order, the two interfaces become alike and the asymmetry disappears. The assignment is therefore an open parameter of the fit and not a property of the material pair, and it is settled by `interfaces`.
10. With `interfaces.mode` `explore`, or for any pair absent from `interfaces.pairs`, assume no assignment: run the fit under each admissible assignment — the wider interlayer on one interface, on the other, and the two equal — and report all of them with their chi2 and their seed spreads. The split is reported as undetermined unless a criterion of this section excludes an assignment, because a difference in chi2 between assignments that is inside the seed spread of section 8, step 4 has not chosen between them.
11. With `interfaces.mode` `constrained`, apply the declaration for the pair: `constraint` `wider_on` orders the two interlayers by `wider_interface`, and by the bound `ratio_min` when one is given; `symmetric` holds them equal; `undetermined` states that no constraint was found, which is not the same as none having been sought. Test `applies_when` against the fitted structure after the fit — a declaration that holds only while the heavy layer orders does not hold when the fit returns it thinner than `heavy_thickness_A_min` — and where the condition fails, discard the declaration and take step 10 instead. Report the split as constrained, naming the declaration's evidence, its method and its detail, because a constraint carried by transmission microscopy or photoelectron spectroscopy is evidence from another measurement, while one carried by assumption is a prior and must read as one.
12. If an order fails, act by the two rules of section 3, the ends of the stack for the level between peaks and the higher orders for the fine structure, before changing anything else. If the first fit passes, do not run further fits except those sections 4, 7 and 8 require.
13. When the fitting cannot be converged, when no setting brings the calculated curve onto the measured one, there are two causes and only two: the measurement is bad, which can be judged from the curve itself (counts, alignment, an aborted or noisy range), or the model is too simple, which is the common case. A model that is too simple is fixed by adding what is missing (a light surface layer of contamination, an interlayer at an interface, a drift through the stack), not by pushing a parameter that stands in for it; a roughness or a density that absorbs an unmatched feature is a sign of the second cause. Peaks have priority over the secondary fringes when the two disagree: the peaks carry the period structure, and an unmatched fringe field is the first place to suspect a missing surface layer.
14. The two roughnesses of a two-material period move the same features of the curve and the fitter finds two minima that differ only in which layer carries the larger sigma. Which of them a fit lands in is decided by the random seed, not by the start model (with `range_seed` the start model plays no part). The assignment is therefore not a criterion: a fit is judged by the peaks, the edge and chi2, and the sigma values are reported as fitted, without a claim about which interface is the rougher one. This is the oldest case of steps 6 to 8, and the same rule: what the seeds do not agree on is not reported as though the curve had fixed it.

## 11. Density

1. A fitted density is a free parameter, never a result. Do not report it as a material property, do not build a design, a rule or a deposition time on it, and do not spend fits determining it.
2. A low fitted density of a thin metal layer near its lower bound is a sign of intermixing at that layer's interfaces, not a density of the material. The bound is still extended and the fit repeated (section 7, step 5), so that the value is the data's and not the bound's, and the reading of it as intermixing stands on the extended fit.
3. A density that ends on the bulk ceiling is reported at the ceiling unless the preset carries a reason for raising it (section 7, step 6). Before reading such a value as a dense layer, check the conditioning: normalizing inside the beam-footprint region and the smoothing pass of section 5 both push a heavy layer's fitted density up.

## 12. Single films

1. A single film of the light material of the design, on the substrate, gives its thickness, and from it the deposition rate, and nothing else: report its sigma and density as undetermined.
2. A one-layer model does not reproduce the critical edge or the fringe contrast of such a film. Do not try to repair that with the resolution (section 8) or the substrate roughness (section 2); neither is the cause. The metal films fit with a one-layer model.
3. The single-film exceptions are not named here: the fitting range starts at `single_film.theta_min_deg` (section 6), the sigma bounds are `single_film.sigma_bounds_A` (section 7), the chi-squared weighting is `chi2.single_film` and the optimizer population is `optimizer.population.single_film` (section 8). Held in the preset, a change of light material needs no change of this text.

## 13. Report

The final report has these slots, in this order, every one filled:

1. Measurement id; the preset id (`preset_id`) and the SHA-256 of the preset file's raw bytes; the substrate id used.
2. θ_max, I_max, background level (section 1); for an `.xrdml` import, also the peak count rate and the counting time the count unit was recovered from (1.4), and the ratio of the highest visible order to I_max (1.5).
3. Sensitivity map (section 3): one line per variant, the feature it moves.
4. Starting model (section 2).
5. Scale as echoed: `scale`, `scale_theta`, `scale_counts`, and from the solve `chi2_scale`, `scale_ratio`, `scale_clamped`, `scale_solve_window` (section 4); whether a renormalization was done and why.
6. Smooth passes (section 5), and, when the preset's 0 was departed from, the reason.
7. `r_min` (section 6).
8. `theta_range` and the reason for its upper end (section 6).
9. Resolution, and the chi2 against resolution scan that chose it (`instrument.resolution_deg.scan_step`, section 8), with the fringe-contrast comparison as a check.
10. chi2 settings (section 8).
11. Optimizer settings and the seeds used (section 8).
12. Mode reported, periodic or profile, with both chi2 values (both fits are always run, section 9), the period drift of the profile fit and its spread across the seeds, and why the reported model was chosen, against `reporting.model_selection.margin_in_seed_spreads` (section 9); for a profile fit, the polynomial order used and the fitted drift coefficients.
13. Bounds (section 7), as first set and as finally used, with every extension made under section 7, step 5 and the value that forced it.
14. Job id of the accepted fit, and the ids of every other fit run.
15. chi2_start and chi2 of the accepted fit.
16. Fitted structure: period, each layer's thickness and sigma; the densities listed as "free parameter, not a result". The spread of each parameter across the seeds, every parameter declared undetermined, and every pair of layers reported as a sum instead of a split (section 10). For a profile fit, the per-period values as well as the mean.
17. `out_of_bounds`, and every value on a bound or within `acceptance.thresholds.near_bound_fraction` of one, with what was done about it: the bound extended and the fit repeated, or, for a density at the bulk ceiling, the reason it was not (section 7, step 6).
18. The order table (section 10).
19. The edge check and the fringe check (section 10).
20. The residual by band (section 10).
21. The verdict against the pass criteria of section 10, criterion by criterion.
22. The saved project name.

## Appendix. What the engine does not fit

1. The engine fits layer thickness, sigma and density, and the period of a repeating stack. Nothing else is free.
2. `background` is refused if freed; read it from the curve (section 1).
3. `resolution` is refused if freed; choose it by the scan of section 8.
4. `scale` is refused if freed; the anchor is set by normalization and the solve of section 4, rule 3 profiles the scale out within its window rather than fitting it.
5. The substrate is refused if freed; take it from the substrate library entry of section 2.
6. These are conditioning, not results, so they must be set correctly before the fit rather than discovered by it.
